Cross-project rules (menus, About, Settings, languages, updater, logging, publishing): skill `~/.claude/skills/moe-apps/SKILL.md`.

Mac app (Rust core + Slint) for the Avid MXF media of edit systems. One app since 2026-11-09 (user decision): Exchange, Check (every `Avid MediaFiles/MXF/<folder>` against its database `msmFMID.pmr`), Projects, Maintain, Tasks. ## Fixed rules
- Checking only reads. The only writes: renaming folders for Media Composer and back, and moving new files on rename back – both only when the user asks. Never delete, never overwrite (check `exists()` first – `rename(2)` replaces an empty folder or a file silently).
- Renaming (`src/rename.rs`): Media Composer only updates folders named with a number (local drive) or `<ComputerName>.<number>` (network drive, `statfs` without `MNT_LOCAL`). Only folders directly in `Avid MediaFiles/MXF` are renamed. The journal (`renamed.json` in Application Support: original name, every MXF file name + size, database stamps) is saved before each rename; an unreadable journal disables renaming. "Ready" = both database files exist and changed since renaming. Renaming back asks about new files (move to new folder / to `1` or `<computer>.1` / keep), missing or changed files and a not yet rewritten database. Media Composer must be closed: `pgrep -x AvidMediaComposer` (not `-f`: AvidBackgroundServicesManager lives in its bundle and always runs).
- `msmFMID.pmr` format is reverse-engineered (`read_pmr` in src/lib.rs, layout in the module comment). Block 1 = names in Mac Roman, leaving out names it can't represent; block 2 = all names in UTF-8 and authoritative. Block 1 is only a plausibility check (not longer, its ASCII names in block 2); the file must end exactly after block 2, otherwise "unreadable" – never guess. Verified against the Exchange test environment and one of the user's media drives (Media Composer 2024 databases with umlauts and Turkish names).
- Names are compared with `key()` (NFC + lowercase). Dot files and subfolders (Avid's "Creating") are ignored.
- Four languages: en, de, fr, es (the user's rule for all apps). Core texts (findings, report) in `Finding::describe` / `report_text` via `pick()`; UI texts English in `@tr()`, translations in the table of `scripts/translations.py`, which writes the three `.po` files and fails if an `@tr` has no entry – run it after every UI text change. Manuals `docs/help/<code>.md` for all four.

- Avid bins: `src/avb.rs` reads `.avb` (format from pyavb, MIT – THIRD-PARTY.md; running pyavb itself is not allowed here, it is only a reference). Parses only mobs (CMPO), source clips, sequences, track-group prefixes, descriptors + locator class; skips everything else. Bin items include hidden file mobs: shown = Master (subclip: usage 2) and Composition with usage 0 (sequence). File mob = source mob with a media file descriptor; its mob ID is the **first** 32-byte ID of the msmFMID.pmr record (`read_pmr_entries`), verified on a real test project. Names in bins are Mac Roman. Checked: all 6583 bins of the user's test projects (path: see local memory, not in the repo) (MC 18.12–26.8) read without error (then with a `mfcheck --bins` that no longer exists; today `mfcheck --projects FOLDER [REQUEST]` reads the bins, `MFC_DRIVES=a:b` sets the drives).

- Avid projects (`src/projects.rs`, tab Projects – formerly `ProjectsWindow`/`AmaWindow`, now steps Missing media (with the AMA line, user 2026-11-25) / Request in `ProjectsPane`, fed by the central scan – see "Projects tab on the central scan" below): project = folder with an `.avp` (no search inside a project – shared projects have more .avp in AvidSharedData), bins without `Attic`. Bin items are all mobs, Media Composer hides most: shown clips = masters, subclips (usage 2), sequences (composition, usage 0). Master usage 1 = render (precompute) master "<sequence>,<effect>,<n>" – their missing files are only counted (`renders`), not listed or requested (test project: 919 render vs 17 real). Result per bin: missing files grouped by name (master clip that owns the file, else file mob name – often just "File" – else first use), each with its uses, shown in `MediaWindow` (see "Missing media window" below). References to mobs in other bins are resolved per project. Available = first ID of every msmFMID.pmr entry whose file is really in the folder, plus MXF files in no database identified by their header (`src/mxf.rs`: essence container data → LinkedPackageUID = file package UMID; material number's first three fields big-endian in MXF, swapped to the pmr/bin layout – verified identical to the pmr ID for all ~8,700 files of samples from three of the user's media drives and the Exchange test environment); dot files (AppleDouble `._`) skipped; a drive silent for 30 s is skipped (`available_media`, hanging macFUSE/network mounts block forever). AMA = media descriptor with extension 0x01 (acfUID of the AMA plugin; `Mob::ama`) – AMA files still carry an MSML locator, so the locator says nothing; 4 test projects: 790 AMA file mobs, none in any msmFMID.pmr – not requested; listed per bin with their uses (`ScanResult::ama_by_bin`) in `MediaWindow` kind 1 ("Show AMA clips…" on Missing media, own open set `ProjectsState::ama_open`, hidden when a new scan starts) and in the saved list. An AMA file whose master clip has a namesake master in the same project with all its media on the drives (linked first, imported later) is left out (`ama_covered`, only counted). Relink = missing file whose source (name of the tape/camera/import source mob below the file mob, `Bin::source_name`, + picture/sound) belongs to an available file mob in the scanned bins (e.g. re-transcoded dailies: new file mob IDs, old bins still point to the old ones) – marked, not requested. "Unmanaged" = file mob without MSML locator (AAF imports) – counted separately, still requested (Exchange only finds what is in Avid MediaFiles). File mob without any locator = no media was ever made (camera sound tracks of camera master clips when only the picture was delivered and sound comes from an external recorder; test project: 839 of 883 "missing") – left out, counted as `no_media`. A source clip points at one track (track number + media kind) of its mob; `Bin::used_tracks` follows only that one (a picture-only subclip must not need the camera sound), all tracks if it is not found. Request = JSON `{format: "mediafiles-exchange-request", version, system, created, files: [{id (64 hex), clip, bin, project}]}`, file `YYMMDD-HHMM_<computer>_Request.mfexchange`; Exchange reads it in `src/exchange/request.rs` (keep both sides in step). Windows that grow stay unpainted below their old height on macOS: every window reports height changes (`CheckWindow`: `changed height => Shared.resized()`) and is wired with `repaint_on_resize!` (app.rs) – use it for any new window.

## Exchange
Core in `src/exchange/` (scan, plan, collect, request, flow with their tests; `use crate::exchange::*`). Rules carried over: never delete a media file, never overwrite one; a database is only delivered/replaced if the target folder ends up exactly like the source (else task "rebuild database"), replaced ones go to `Avid MediaFiles/Exchange-Backup/`; present = same name + hash anywhere on the other side, same name + different hash = task; import verifies the whole delivery first and only imports a complete one; `key()` compare, `write_atomic`. Hardening (review 2026-11-25, each with a test in collect.rs): a database is only collected while its source folder still holds exactly the scanned MXF files (else task "rebuild database"); collect and import first check free space (`check_space`, needed + 1 GB `RESERVE` per drive, else nothing is written); import stages both new database files as hidden `.<name>.exchange-new` next to the old ones and only swaps when both are there (old pair stays whole otherwise), errors there become problems instead of aborting; `copy_verified` writes and reads back with `F_NOCACHE` (`no_cache`) and never leaves an `.exchange-part`; `Manifest::load` rejects names that are not one plain path part (`path_part`, also used by `safe_path`); `mxf_names` skips dot files (AppleDouble `._x.mxf`). I/O tests (2026-11-25): `tests/exchange_io.rs` (16 scenarios, every file hashed before/after: sender unchanged, receiver only gains files, replaced databases in the backup, no `.exchange-part`/`.exchange-new`/`.tmp` left; helpers in `tests/common`) and `tests/exchange_faults.rs` (`#[ignore]`: full drive, drive filling up mid-copy (another program fills it after the space check – ENOSPC, 2026-11-25), read-only drive, drive pulled out mid-import, app killed (SIGKILL, child process) during collect, import and database placing – afterwards no file under its final name is wrong and a second run finishes). `scripts/exchange-disks.sh [filter]` runs both on disk images (APFS, case-sensitive APFS, exFAT, HFS+; mounted outside /Volumes, receiver in a non-writable parent like /Volumes) – about 3 min; `MFC_IO_ROOT`/`MFC_IO_B`/`MFC_IO_B_IMAGE` and `MFC_LAB_RESERVE` (lab only) are set there. Goldfish review fixes (2026-11-25): "Don't send" is `Options::skip` (a same-name drive on the other side no longer catches it); a database is not placed for a delivery folder where any media copy was refused (`failed`); the swap moves the old pair aside first and puts it back on any error (never one old + one new file); a delivery may only list `*.mxf` (no leading dot) and the two database files, each path once by `key`; collect refuses while Media Composer runs; collect and import hold `WORK_BUSY` (`begin_exchange`) and import refuses while folders are renamed (`txt-renames-open`). A delivery whose `to` is not this computer (`computer_name`, key compare) is refused when chosen (user 2026-11-25), text `txt-not-for-us`. File names (2026-11-22, user: the old standalone app name must not appear anywhere, its old files are NOT read any more): `.mfexchange` manifests/requests, formats `mediafiles-exchange-manifest/-request/-delivery`, `exchange-delivery.json`, `Exchange-Backup/`, `Tasks.txt`/`Aufgaben.txt`. Data folder `~/Library/Application Support/MediaFiles Check/Exchange/` (checksum cache, last-manifest.json, mappings.json; `exchange_dir`). Task texts (`Task::describe`) and the delivery's task file are in all four languages via `pick` (file name `Aufgaben.txt` for de, else `Tasks.txt`). UI wiring `wire_exchange` (app.rs); worker threads never hold `Rc` – they call a global callback (`Tasks.reload`, `Inventory.scanned`) via `invoke_from_event_loop`. Tested end to end on two disk images (scan, compare with mapping + merge, collect, import, byte-identical). Since 2026-11-14 (user decisions) the RECEIVER decides on import, not the sender on compare: per delivery folder Merge (same name) or Own folder `<sender>_<folder>` (`collect::own_folder_name`; existing one = files go into it), per delivery drive "as there" or Separate (media → drive X, render files → drive Y, render = `mxf::file_info` render mark; unknown counts as media) – `collect::Targets`, `Incoming::{renders, folders}`. ## Updates
`src/update.rs`: port of Mountpoint's Updater.swift through /usr/bin/curl; checks 5 s after start, every 6 h and from Settings (Updates tab); main window: floating `UpdateCard` at the bottom centre (user 2026-11-25, like Fona/CineMosaic – the content never moves; × hides it until the next start; an error `Note` then sits above it), Settings › Updates keeps `UpdateOffer`/`UpdateStatus`; install = download → ditto → bundle id + `MediaFilesCheckRelease` (Info.plist, written by the build script) == tag + `codesign --verify --deep --strict` → old app to ~/.Trash → new app in place → shell waits for the pid and reopens. Release tags `v<version>`, asset `MediaFiles-Check-<version>.zip`. Beta 1 has no updater – users of it update by hand once. `UPDATE_IT=1 cargo test live_github` asks GitHub. Update signature (since 1.0.0-beta.6): every zip is signed with Ed25519 (`<zip>.sig`, `scripts/update-key.swift`, private key in the login Keychain as "MediaFiles Check update key"); `UPDATE_APP.public_key` holds the public half; `newest_release` ignores releases without `.sig`, `download` checks it before unzipping (`signature_valid`, crates ed25519-dalek + base64). build-mac-app.sh signs only if the Keychain key matches, else prints "NOT SIGNED". Never replace the key (installed apps trust it). Older betas (≤ beta.5) don't check signatures and update normally.

Every change of the limit goes through a warning card in the settings window (field + "Change…"/Enter → `limit-ask`; Cancel reverts the field) – the user wanted one fixed rule instead of a per-group choice: groups are ALWAYS laid out anew for the current limit.
Group = main folder + "<base>-rebalanced-<n>" folders in the same MXF folder, found BY NAME (base = name without ".<digits>"; also works for other workstations). `plan()` sorts all MXF files of the group by creation date (fallback modification date): oldest `per` → first rebalanced folder, … youngest stay in the main folder; the files of one clip (same master mob ID: msmFMID.pmr second ID, else MXF header material package 0x4401 – needed while databases are set aside, so a second run plans no moves) stay in one folder (`layout`: a clip that does not fit starts the next folder, only a clip larger than `per` is split – idea from MediaMuster, 2026-11-10); existing rebalanced folders keep their names, missing ones get the next free number, emptied ones holding only leftovers (`is_leftover`: msmFMID.pmr, msmMMOB.mdb, an empty "Creating" folder, hidden files) go as a whole into "<drive>/MediaFiles Check Database Backups/<time> <name>" (`move_leftover`); with anything else in them only their database is set aside and they are kept (never deleted with content). Lower limit → more folders, higher → files move back. Layout comes from the drive, so an interrupted run is finished by the next one. "Find full MXF folders…" (`full_folders`) lists groups where something would move; groups with a folder currently in renamed.json are `blocked` (names reserved).
Media Composer's own main folders ("1" local, "<computer>.<n>" network, `is_mc_folder`) → page `askname` before the run: we recommend a name of its own (`check_name`: not empty, no "/" ":" leading dot, not an MC name, no "-rebalanced-", not taken); the main folder is renamed (one rename) and the group gets the new name, old "1-rebalanced-N" folders fold into it. "Keep the name" skips.
History: rebalanced.json, ONE entry per group (`Journal::find` by mxf + main name), saved before anything moves; fields `renamed_from`, `folders`, `files`, `changed` (folders whose databases need rewriting; an unfinished run's list is merged into the next), `db_done` (old entries without it count as done; old `moved` lists still read). Start / "Rewrite databases" (`rewrite_runs`): set aside each changed folder's database and rename those Media Composer does not update for it (renamed.json flow). Undo: all media files back into the main folder (`plan` with per = MAX), emptied folders removed, old name back if free, main database set aside (+ rename for MC if needed); stops if a group folder is renamed for MC. Media Composer must be closed for rebalance, Start and undo. Tested end to end on a sparse disk image (200 files, limits 150 → 100 with rename).
